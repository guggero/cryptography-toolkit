BIP-446: Template Hash explorer

Explanation

BIP 446 proposes a new tapscript op code, OP_TEMPLATEHASH, that pushes a hash of the transaction that spends an output onto the stack. A script can compare that hash with a fixed value, or check a signature over it, and so restrict what the spending transaction looks like.

The interesting part is what the hash leaves out. It commits to the version, the lock time, the sequence numbers of all inputs, all outputs, the index of the input and its annex. It does not commit to the outputs being spent: neither which ones, nor their value, nor their script. A normal signature commits to all of those.

On this page you can edit a transaction and see which changes move the template hash. An output is locked to the transaction with the script OP_TEMPLATEHASH <hash> OP_EQUAL, and every edit is checked by really spending that output with the script engine of btcd.

The op code is a proposal and not active on any Bitcoin network.

  • BIP 448: Taproot-native (Re)bindable Transactions
