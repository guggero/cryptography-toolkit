Elliptic Curves

Explanation

An elliptic curve is the set of all points (x, y) that satisfy the equation y² = x³ + a·x + b (the "short Weierstrass form"), plus one extra point O "at infinity". The numbers a and b are the coefficients of the curve; Bitcoin's curve secp256k1 uses a = 0 and b = 7, so its equation is simply y² = x³ + 7. Because of the y², the curve is symmetric around the x-axis: if (x, y) is on the curve, so is (x, −y).

Adding points. What makes elliptic curves useful for cryptography is that their points can be "added" with a geometric rule: draw the straight line through P and Q. It hits the curve in exactly one more point. Mirror that third point across the x-axis and call the result R = P + Q. To add a point to itself (2P = P + P) there is only one point, so the tangent line at P is used instead. If the line is vertical (Q is the mirror image of P, written Q = −P) there is no third point: the result is the point at infinity O, which plays the role of zero (P + O = P, P + (−P) = O). The mirroring step is what makes the rule behave like a proper addition ((P + Q) + R = P + (Q + R)), so the points of the curve form a group. In formulas, with the slope m of the line: 
m = (yQ − yP) / (xQ − xP)        (P ≠ Q)
m = (3·xP² + a) / (2·yP)             (P = Q, the tangent)
xR = m² − xP − xQ
yR = m·(xP − xR) − yP
Which numbers? The equation and the addition rule make sense in any number system that has the four basic operations. The three buttons above the plot step through the abstraction:
  • ℝ, the real numbers. Infinitely many points on a smooth curve. The geometry is easiest to see here, but the arithmetic involves square roots and rounding, which is useless for cryptography: two computers would never agree on the last digit.
  • ℤ, the integers. Only whole-number coordinates are allowed, so the curve becomes a trail of dots on the grid: every grid point within half a step of the curve, the way a line is drawn on a pixel screen. The line through P and Q still works, and the dot closest to where the line meets the curve again becomes the third point. That last step is a cheat, and the table shows it: applied to whole numbers, the formulas produce fractions (the slope m is a quotient), so the exact result is almost never a grid point. The integers lack division; they are not closed under the rule. Genuine integer solutions are rare: y² = x³ + 7 has none at all (V. A. Lebesgue, 1869), while y² = x³ + 17 has (−2, ±3), (−1, ±4), (2, ±5), (4, ±9) and a few more.
  • 𝔽p, the integers modulo a prime p. Every coordinate is a whole number between 0 and p−1 (the box on the plot), and after every addition, subtraction or multiplication the result is reduced to its remainder when divided by p. Such a number system is called a finite field, and here division works again: instead of dividing by d you multiply by its modular inverse d−1, the number with d · d−1 ≡ 1 (mod p). Such an inverse exists for every non-zero d precisely because p is prime, which is why the exact same addition formulas keep working word for word, with no rounding needed. The picture looks completely different though: the dots scatter over the whole box, and the "line" through P and Q wraps around the edges like on a torus, yet still hits exactly one more point of the curve. The faint curve in the background is the same equation over ℝ, for reference: an integer point that lies on it exactly is also a point of every 𝔽p (reduce its coordinates modulo p), which is why such points survive a switch of the number system.
Scalar multiplication and keys. Adding P to itself repeatedly gives P, 2P, 3P, …, kP. Over a finite field these multiples hop around seemingly at random. Computing kP from k and P is fast (double-and-add), but given only P and kP there is no known efficient way to recover k: the elliptic curve discrete logarithm problem. That asymmetry is exactly what ECC keys are built on: the private key is a scalar k, the public key is the point k·G for a fixed, public generator point G. The ECC/ECDSA page does this on the real secp256k1 curve, where p = 2256 − 232 − 977 and the number of points n is itself prime, so every point except O generates the whole group. The default toy curve with p = 61 happens to share that property: it has exactly 61 points, and 61 is prime.
